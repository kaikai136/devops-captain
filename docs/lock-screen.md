# 用户菜单锁屏页面

锁屏页面对齐本地 naive-ui-admin 的双阶段交互：纯黑锁定页展示时间、日期、电池动画及网络状态；点击锁图标或按键进入密码页。

- 解锁继续调用 Captain 原有 `/api/auth/unlock/`，不建立新的登录流程。
- 回车、密码框右侧箭头和“进入系统”使用同一个提交入口；空密码不提交，请求期间禁止重复操作。
- “返回”清空密码和错误，再次展示锁定页；“重新登录”复用当前退出登录流程。
- 解锁成功后恢复原工作区；错误密码或请求失败不会主动清除锁定状态。
- 不支持电池 API 或访问失败时显示 `--%` 和“电池信息不可用”，不使用虚构电量。时间、网络和电池监听仅在锁定期间运行。
- 锁屏区域限制焦点和键盘事件，兼容小屏和系统减少动态效果偏好。不新增自动锁屏或顶部独立入口。

无需安装依赖、修改后端接口或执行数据库迁移。

验证命令：

```powershell
cd frontend
npm run test:run
npm run build
cd ../backend
python manage.py test accounts.tests.SessionLockTests --noinput
```

浏览器验收：从用户菜单锁屏，检查时钟及电池状态；点击锁图标和使用键盘进入密码页，检查返回、空密码、错误密码、正确密码和重新登录；刷新锁定会话应继续显示锁屏，解锁后应回到原工作区。在桌面及手机宽度下检查表单可见且可操作。
