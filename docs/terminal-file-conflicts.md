# 终端文件保存冲突检测

全量终端的文本编辑器在打开文件时对读取到的原始字节计算 SHA-256，保存成功后使用实际提交的字节更新基线。BOM 和换行符参与摘要计算；只修改时间而未修改内容不会触发冲突。

保存接口 `POST /api/web-terminal/hosts/<host_id>/files/content/update/` 使用 multipart 表单：

- `path`：远端文件路径。
- `file`：完整文件内容。
- `expected_hash`：打开时或上次保存成功后的 SHA-256 小写十六进制摘要，普通保存必须提供。
- `force`：`true` 或 `false`，默认 `false`；仅用户明确选择强制保存时发送 `true`。

后端先完整写入临时文件，再通过远端 `sha256sum` 校验目标文件，最后替换原文件。摘要不一致返回 HTTP 409，JSON 包含 `code: file_changed` 和 `error`，不替换原文件，并清理临时文件。校验命令不可用或执行失败时保存失败，不降级为覆盖。远端需要提供 `sha256sum`。

冲突弹窗提供取消、放弃并重新加载、强制保存。取消和关闭弹窗保留未保存内容；重新加载成功后才替换编辑内容，失败保留草稿；强制保存仍进行权限检查和完整写入。遵循现有弹窗约定，点击遮罩不关闭弹窗。

这是保存前的乐观并发校验，不对外部进程加锁，不能阻止外部程序在最终校验与替换之间写入文件。无需数据库迁移；前后端应一起部署，旧客户端未提交摘要的普通保存会被拒绝，需要刷新页面重新打开文件。

手动验收：打开远端文本文件并编辑，在另一终端将远端内容改为同样长度的不同内容，分别用保存按钮和 Ctrl/Cmd+S 确认出现冲突弹窗；依次验证取消保留草稿、重新加载最新内容，以及强制保存覆盖远端。另检查 BOM、CRLF、空文件和符号链接目标保存。
