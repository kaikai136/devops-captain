# 批量执行性能与状态统计设计

## 目标

解决批量执行期间页面卡顿、重复请求和大量结果渲染问题，并将执行记录列表的“状态”列改为直接显示成功与失败数量。

状态列示例：

`成功 114 / 失败 3`

执行过程中也要根据后端返回的计数实时更新。

## 范围

- 仅调整批量执行页面的任务列表轮询和任务详情加载流程。
- 任务列表继续使用现有轻量任务列表接口。
- 任务详情仅在用户打开详情弹窗时加载主机执行结果。
- 详情弹窗打开且选中任务处于排队或执行中时，继续轮询详情。
- 增加轮询防重入，避免慢请求未结束时启动下一次请求。
- 轮询间隔调整为 5 秒。
- Shell 和文件上传任务都使用相同的列表轮询优化。
- 状态列显示 `successCount` 和 `failedCount`，不再只显示任务级状态徽标。

## 数据流

### 任务列表

`loadTasks()` 只调用 `listBulkExecutionTasks()`，更新分页数据、选中任务 ID 和空列表状态，不主动调用 `selectTask()`。

这样在详情弹窗未打开时，页面不会获取或渲染每台主机的 stdout、stderr、传输记录等大字段。

### 任务详情

- `openTaskDetail()` 主动调用 `selectTask()`，加载详情后再打开弹窗。
- 弹窗关闭后，轮询只刷新列表，不刷新详情。
- 弹窗打开时，轮询先刷新列表；若选中任务仍在排队或执行中，再刷新该任务详情。
- 切换任务或重新打开详情时，保留现有的结果展开状态和上传文件树重置逻辑。

### 轮询

- 轮询开始前清理旧定时器。
- 每轮执行前检查是否已有请求进行中。
- 一轮只执行一次任务列表请求；详情刷新由弹窗状态决定。
- 组件卸载时清理定时器并结束后续状态更新。

## 状态展示

任务列表“状态”列显示：

```text
成功 {task.successCount} / 失败 {task.failedCount}
```

计数缺失时按 `0` 展示。任务整体状态仍保留在任务对象中，用于筛选、轮询和详情弹窗，不额外改变后端状态语义。

“退出码”列保持现有行为，避免扩大本次改动范围。

## 测试

更新 `frontend/src/features/bulk-execution/__tests__/bulkExecution.structure.test.ts`，覆盖：

- `loadTasks()` 不在列表刷新中主动请求详情。
- 详情弹窗打开后才触发详情刷新。
- 轮询存在防重入状态。
- 轮询间隔为 5 秒。
- 状态列使用成功和失败计数。
- 旧的仅显示任务状态徽标的列表实现被移除。

运行：

```text
npm run test:run -- src/features/bulk-execution/__tests__/bulkExecution.structure.test.ts
npm run build
git diff --check
```

## 非目标

- 不修改批量执行后端任务状态定义和数据库字段。
- 不修改 Shell 或文件上传的执行协议。
- 不在本次改动中引入详情分页或虚拟列表。
- 不改变任务筛选、分页、取消、删除和重新执行行为。
