# 浏览器性能分析：2026-10-19

分析输入：`Trace-20261019T191911.json.gz`，本地生产预览 `127.0.0.1:4173`。附件仅作为性能数据读取。

## 结论与测量范围

录制选定窗口为 65.078 秒，包含刷新、主机详情和 Docker 分类切换、打开终端。根据 Renderer 主线程的完整 `RunTask` 事件统计，忙碌时间约 6.467 秒，占窗口 9.94%。这是录制线程的忙碌比例，不是整台机器的 CPU 使用率。

整体交互响应较好，主要问题是远端数据等待和局部渲染峰值。以下数据来自修改前的录制，不代表优化后的结果。

## 优先优化方向

### 1. 远端采集等待：收益最大

- 主机监控请求约 1.95～2.88 秒，Docker 容器成功请求约 3.56～4.78 秒，镜像请求约 2.84 秒。
- 这些成功请求的首字节等待几乎占满总耗时，浏览器下载 JSON 的时间很短。需要进一步在服务端计时，区分 SSH 建连、命令执行和采样等待。
- `backend/web_terminal/services/monitoring.py` 的命令包含 `sleep 1`，用于 CPU/网络两次计数采样，不能直接删除，否则速率计算会失真。
- `backend/web_terminal/services/containers.py:get_remote_containers` 分别调用一次性 SSH 命令获取 `docker ps` 和 `docker stats`；`commands.py:run_one_shot_ssh_command` 每次建连并关闭。
- 建议先在一次请求内复用 SSH 连接，再考虑把容器列表与资源统计分开返回。持续监控可评估服务端采集与短期快照缓存，需保证权限隔离、连接回收、超时和数据新鲜度。

### 2. 页面切换的同步布局

录制使用的 `system-DMjpmgg7.js` 与分析时本地构建文件一致，可以核对压缩代码：

- 约 12.377 秒和 14.368 秒的长任务分别约 104.1 ms、86.3 ms；Element Plus `ElSelectDropdown` 挂载时读取 `offsetWidth`，分别触发约 36.7 ms、23.8 ms 布局。
- Element Plus 滚动条 `update` 读取尺寸所触发的 Layout 共约 74.0 ms，相关样式更新约 38.4 ms。
- 约 58.035 秒终端初始化任务约 85.8 ms，`scrollActiveTerminalTabIntoView` 中的 `scrollIntoView` 触发布局约 25.4 ms。

建议减少同一更新周期内交错的 DOM 写入和尺寸读取；对已在可视区域的终端标签避免重复平滑滚动。单纯将同步测量放进微任务并不能消除强制布局。

### 3. 图表、后台采集与重复刷新

- CPU 采样中 zrender 文件自耗时约 427 ms，echarts 约 154 ms；采样值仅作热点线索。
- `DashboardChart.vue` 每次设置选项使用 `notMerge: true`，监控曲线刷新会完整重建选项状态。可针对稳定 series id 评估增量更新，但必须测试删除曲线、空数据、主题切换等情况。
- 主机详情通过 `v-show` 保留。现有测试明确要求后台继续采集和保留连续曲线，因此本轮保留采集行为。可后续将数据采集和不可见图表绘制分离。
- Docker 分类每次点击强制刷新，也是现有测试的明确行为。若改为短期缓存，需要同时设计独立刷新入口和刷新语义。
- 数据库传输中心已有 WebSocket，同时每 5 秒请求任务列表；可以评估连接健康时降低兜底轮询频率，但需保留断线恢复和完成通知。

## 本轮已实施

1. `useTerminalResize.ts` 增加按终端合并的帧调度。ResizeObserver 与页面主动调整共用队列，同一帧对同一终端最多执行一次排队的 fit；执行前再次检查是否可见，关闭终端时取消任务。立即 fit 会替代已排队的任务。
2. `WebTerminalPage.vue` 的延后尺寸调整使用上述调度，避免多次创建独立帧回调。
3. `DashboardPage.vue` 复用 `Intl.NumberFormat`，避免模板重渲染和图表 formatter 调用时反复创建格式化器。修改前 CPU 采样中此函数自耗时约 34 ms，属于小幅优化。

验证：终端尺寸调度、终端页面结构和主机详情结构共 24 项测试通过。新增测试覆盖重复请求合并、最新尺寸、可见性切换、销毁清理和立即 fit 替代排队任务。

`npm run build` 通过。构建仍提示大于 500 kB 的 chunk：共享 system 约 1,067 kB、文件工作区约 621 kB（压缩前）；这是后续按需加载和拆包的候选点，本次录制中远端采集等待更突出。

未进行修改后的同场景浏览器录制，暂不报告耗时改善百分比。建议在相同窗口尺寸、相同主机及数据下复录，比较终端初始化和拖动的布局次数、长任务分布；接口优化则单独比较首字节等待。内存应在反复关闭详情/终端、回到相同页面并回收垃圾后比较。
